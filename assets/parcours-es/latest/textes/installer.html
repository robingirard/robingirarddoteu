Installer et vérifier en dix minutes

Installer l'environnement épinglé des cas POMMES dans un venv (pommes 0.11.0, pommes-craft 0.6.0, pommes-assistant 0.5.3), lancer un test de contrôle d'une minute, savoir quoi faire si ça casse ; sans installation possible, le JupyterHub des Mines ou le repli sur Colab.

Le notebook du premier modèle, lundi à 14 h, puis les cas des mini-projets tournent dans un même environnement Python. Cette page l'installe, le vérifie par une commande et dit quoi faire quand ça casse.

Trois façons de faire tourner les cas

où ce qu'il faut installer, puis tester (mesuré) §
sur votre ordinateur Python 3.12 ou 3.13, et git 1 à 3 min, puis 35 s à 2 min 1 à 7
sur le JupyterHub des Mines, dans le navigateur un compte des Mines 1 min, puis 74 s 8
sur Google Colab, dans le navigateur un compte Google 3 min dans chaque notebook, puis 2 à 3 min 9

Pour le notebook du premier modèle, les trois conviennent : sur Colab, sa première cellule installe tout elle-même. Pour le mini-projet, à partir de mardi, installez si possible sur votre ordinateur : vous y gardez votre travail et les cas tournent hors ligne. Si l'installation bloque et que la section 7 n'y fait rien, passez au JupyterHub des Mines. Sans compte des Mines, prenez Colab, en sachant que tout y est effacé à la fin de chaque session.

1. Ce qu'il faut avant de commencer

  • Python 3.12 ou 3.13 (python3 --version). Testé en 3.12. pommes-assistant, dans le même environnement, demande 3.12 au moins.
  • pip et venv, livrés avec Python. Pas besoin de conda, ni de droits d'administrateur, ni de solveur commercial : le solveur HiGHS vient avec le paquet highspy.
  • Du réseau, une seule fois, pour les paquets. Les cas 0 et A à E lisent ensuite leurs données dans le dépôt et tournent hors ligne.
  • git, ou à défaut l'archive ZIP du dépôt, téléchargée depuis la page GitLab du dépôt (bouton Code).

Si l'un de ces points vous arrête, installer Python ou git par exemple, demandez de l'aide aux encadrants. Une IA générative dépanne aussi très bien : donnez-lui votre système (Windows, macOS ou Linux), la commande tapée et le message d'erreur complet.

2. Installer : quatre commandes

git clone https://git.persee.minesparis.psl.eu/energy-alternatives/pommes_studies/pommes-case-studies
cd pommes-case-studies
python3.12 -m venv .venv && source .venv/bin/activate   # Windows : .venv\Scripts\activate
pip install -r requirements.txt

La troisième ligne crée le venv, un dossier .venv qui contient le Python et les paquets du cours, à part du reste de la machine, puis elle l'active : le terminal affiche alors (.venv) en tête de ligne. C'est ce que cette page appelle « venv activé ». Dans un nouveau terminal, réactivez-le depuis la racine du dépôt avec source .venv/bin/activate (Windows : .venv\Scripts\activate).

Sur la machine de référence, pip install -r requirements.txt dans un venv neuf, sans cache, a pris 43 s le 17/11/2026, et pip check n'a trouvé aucun conflit. Comptez une à trois minutes.

Ce que requirements.txt installe, et pourquoi c'est épinglé :

paquet version rôle
pommes 0.11.0 le modèle d'optimisation
pommes-craft 0.6.0 l'interface objet pour écrire un modèle en Python
pommes-assistant 0.5.3 l'assistant en langage naturel pour écrire une étude pommes, avec ses options ([all])
linopy 0.10.1 la couche qui construit le programme linéaire
highspy 1.15.1 le solveur HiGHS
hdf5plugin 7.1.0 lecture des NetCDF compressés ; import pommes échouait sans lui avant pommes 0.6
pandas 3.1.1 tableaux ; API mouvante
polars 2.1.0 lecture des Parquet
numpy 2.5.4 calcul numérique
xarray 2026.9.0 tableaux étiquetés, le format de pommes
jupyter 1.1.1 les notebooks

Les grilles complètes versionnées du dépôt (results.json) ont été calculées en pommes 0.9.0 ; rejouées en 0.11.0 le 17/11/2026, leurs grilles rapides redonnent les mêmes chiffres. Ne mettez rien à jour pendant la semaine : les valeurs attendues des consignes dépendent de ces versions.

3. Vérifier : une commande, une minute

Depuis la racine du dépôt, venv activé ((.venv) en tête de ligne) :

python A_batteries/grid.py --rapide

Le script garde les séries de prix centrales du cas A et fait 10 résolutions HiGHS. Relevé sur un MacBook Pro M3 Max : 34 à 36 s sur trois essais ; 60 s sur un PC portable ThinkPad P14s Gen 6 ; comptez 1 à 2 minutes sur un portable ordinaire. HiGHS n'affiche rien : son journal va dans un fichier. Ce qu'on doit voir :

verdict 1/2 : 7 séries, 11 s (12 s en tout)
verdict 2/2 : 6 séries, 8 s (10 s en tout)
n-ième GW : tyndp2024, σ = 15 €/MWh → 24.9 €/kW/an (0.9 s)
n-ième GW : tyndp2024, σ = 60 €/MWh → 13.7 €/kW/an (0.8 s)
n-ième GW : tyndp2026, σ = 15 €/MWh → 17.8 €/kW/an (0.8 s)
...
n-ième GW : fos_sur_mer, σ = 60 €/MWh → 36.9 €/kW/an (0.9 s)
results_rapide.json : 10 résolutions, 37 s      (le temps varie, le reste non)

Les chiffres en €/kW/an doivent être identiques aux vôtres : modèle linéaire, données figées. Seuls les temps changent.

Si vous êtes pressé, un test plus court contrôle le lecteur de prix et un premier modèle pommes_craft en 2 s :

python tests/test_prices.py

Il affiche d'abord la liste des paramètres que pommes remplit par défaut (Missing variables in input dataset. Adding defaults:, puis flexibility_demand: 0.0…), puis test_format : ok, refusé comme attendu : ..., test_refuse_fichier_modifie : ok et test_net_import : ok. Trois lignes : ok en tout.

4. Ouvrir un notebook

jupyter lab

Le navigateur s'ouvre sur l'arborescence du dépôt. Commencez par 00_prix/notebook.ipynb (les jeux de prix), puis A_batteries/notebook.ipynb. Les notebooks sont en anglais et déjà exécutés : lisez d'abord, relancez ensuite. Ils relisent le results.json versionné et ne refont que quelques résolutions, une minute environ pour le cas A. Lancez jupyter lab depuis le venv activé, sinon le noyau ne trouvera pas pommes.

Un notebook téléchargé depuis le parcours, celui du premier modèle par exemple, se place dans le dépôt, à sa racine ou dans un de ses dossiers : il y prend son code et ses données. Posé ailleurs, sa première cellule s'arrête et dit quoi faire.

Dans VS Code, avec les extensions Python et Jupyter, pas besoin de jupyter lab : ouvrez le dossier du dépôt (File › Open Folder), puis un notebook, et choisissez en haut à droite Select Kernel › Python Environments › .venv. VS Code trouve seul le venv du dossier. Son terminal intégré (Terminal › New Terminal) sert aussi pour les commandes des sections 2 et 3.

Avec un autre outil, le Jupyter d'Anaconda par exemple, enregistrez une fois le venv comme noyau, venv activé :

python -m ipykernel install --user --name pommes-cases --display-name "Python (pommes-case-studies)"

Choisissez ensuite ce noyau à l'ouverture du notebook (Kernel › Change Kernel). Un autre noyau, même s'il connaît pommes, peut porter de vieilles versions : la première cellule le signale par une ligne « Attention ».

Tout est dans le dépôt, rien n'est téléchargé à l'exécution et aucun jeton n'est demandé.

Le lecteur compare l'empreinte SHA-256 de chaque fichier à celle du datapackage.json et refuse un fichier modifié : test_prices.py le vérifie. Sources et licences : les README.md de ces dossiers.

6. Combien de temps prend un cas

Temps du README du dépôt, MacBook Pro M3 Max, HiGHS par défaut, 8 760 heures, mesurés le 17/11/2026 avec l'environnement du cours. Un portable plus modeste ira 2 à 3 fois moins vite.

modèle taille du LP résolution HiGHS
une zone au prix exogène, batteries (cas A), une série 0,04 à 0,22 M colonnes 0,4 à 0,8 s, plus 1 s de construction
un site de vapeur (cas E), cinq configurations 0,48 M colonnes 4 à 5 s
la France de 2035, parc fixé, une année météo (cas B, C) 0,35 M colonnes environ 2 s
idem, 10 années météo empilées (cas C) 3,5 M colonnes 30 s
un site d'hydrogène sans règle (cas D), six configurations 0,74 M colonnes 49 s
un site d'hydrogène sous règle horaire (cas D), trois sites 0,34 M colonnes environ 6 min

Une grille complète prend 6 à 20 minutes de résolution cumulée, champ temps_total_s des results.json (calculés en pommes 0.9.0) : B 356 s, C 470 s, E 502 s, A 1 177 s. Le cas D cumule 7 009 s, soit 23 minutes de mur sur 6 cœurs ; ses sites sous règle sont environ 1,7 fois plus lents en pommes 0.11.0. Vous n'en avez pas besoin : les résultats sont versionnés.

7. Si ça ne marche pas

Trois pannes fréquentes.

  1. CERTIFICATE_VERIFY_FAILED sous macOS, avec le Python de python.org. Ce Python n'a pas de magasin de certificats tant qu'on n'a pas lancé une fois Install Certificates.command, dans le dossier Python des Applications. Variante : export SSL_CERT_FILE=$(python -m certifi). Cela touche surtout les notebooks 2025 de legacy_tp2025/, qui téléchargent des données au premier passage ; les cas 0 et A à E n'ont pas ce problème. La même panne touche le téléchargement du catalogue par pommes-assistant (pommes-assistant catalogue, ou un source: {kind: catalogue, ...} dans un StudySpec) : même remède.
  2. ModuleNotFoundError: No module named 'pommes' dans un notebook. Le noyau Jupyter n'est pas celui du venv. Fermez Jupyter, activez le venv, relancez jupyter lab depuis la racine du dépôt.
  3. pip ne trouve pas une version (No matching distribution found for pommes-assistant…), ou échoue à compiler. Votre python3 n'est pas en 3.12 ou 3.13. Recréez le venv avec la bonne commande, python3.12 -m venv .venv ; sous Windows, py -3.12 -m venv .venv.

Une autre panne : copiez le message d'erreur complet et montrez-le à un encadrant, ou à une IA générative avec votre système et la commande tapée.

Une dernière situation n'est pas une panne : pas de Python installable sur la machine (poste verrouillé). Passez au JupyterHub des Mines, section 8, ou au repli Colab, section 9.

8. Sans installation : le JupyterHub des Mines

Si vous avez un compte des Mines, les cas tournent aussi sur le JupyterHub de l'école, dans le navigateur. Essayé de bout en bout le 24 novembre 2026 : installation, tests de contrôle et notebook du cas A.

  1. Ouvrez jupyterhub.persee.minesparis.psl.eu et connectez-vous avec votre compte des Mines : en identifiant, votre adresse électronique des Mines en entier (par exemple prenom.nom@minesparis.psl.eu), avec le mot de passe de ce compte. JupyterLab s'ouvre sur un dossier vide.
  2. Ouvrez un terminal (File › New › Terminal, ou la tuile Terminal du lanceur) et tapez les cinq commandes ci-dessous. Ce sont celles de la section 2, plus une dernière ligne qui fait connaître le venv à JupyterLab :
git clone https://git.persee.minesparis.psl.eu/energy-alternatives/pommes_studies/pommes-case-studies
cd pommes-case-studies
python3 -m venv .venv && source .venv/bin/activate   # le python3 du hub est déjà en 3.12
pip install -r requirements.txt
python -m ipykernel install --user --name pommes-cases --display-name "Python (pommes-case-studies)"

pip install y a pris une minute, et pip check n'a trouvé aucun conflit. Le dépôt et son venv occupent 1,6 Go dans votre dossier personnel, qui est conservé d'une connexion à l'autre : l'installation se fait une seule fois pour la semaine.

  1. Vérifiez comme à la section 3, dans le même terminal, où (.venv) est affiché en tête de ligne : python A_batteries/grid.py --rapide y a pris 74 s, deux fois le temps du MacBook Pro M3 Max, avec les mêmes €/kW/an. Dans un nouveau terminal, réactivez d'abord le venv : cd pommes-case-studies && source .venv/bin/activate.
  2. Ouvrez les notebooks depuis l'explorateur de fichiers de gauche, sans lancer jupyter lab : vous êtes déjà dedans. Choisissez le noyau « Python (pommes-case-studies) » (Kernel › Change Kernel). Le noyau proposé par défaut, « Python 3 (ipykernel) », est celui du hub, sans les versions épinglées du cours. Le notebook du cas A s'y exécute en entier en 1 min 40 s.

La machine est partagée par tous ceux qui s'y connectent. Ne relancez pas une grille complète, celle du cas D surtout : les résultats sont versionnés (section 6).

9. Le repli : Google Colab

Si l'installation échoue, que la section 7 n'y fait rien et que le JupyterHub ne vous est pas ouvert, les cas tournent sur Google Colab, avec un compte Google. Essayé de bout en bout le 23 novembre 2026 : le notebook du cas A y tourne.

Le notebook du premier modèle, et ceux que le parcours propose au téléchargement, font seuls les étapes 3 et 4 ci-dessous : leur première cellule clone le dépôt, installe les paquets et vous demande une fois de redémarrer la session. Importez-les (étapes 1 et 2), puis suivez ce que cette cellule affiche. Les étapes 3 à 5 valent pour les notebooks des cas, pris dans le dépôt.

  1. Ouvrez Google Colab et connectez-vous avec votre compte Google.
  2. Importez un notebook du dépôt dans Colab. Téléchargez-le depuis la page GitLab du dépôt : ouvrez le fichier, A_batteries/notebook.ipynb par exemple, puis son bouton de téléchargement. Dans Colab, faites ensuite Fichier › Importer un notebook. Tous les notebooks des cas s'appellent notebook.ipynb : si vous en téléchargez deux, renommez-les (A_batteries.ipynb, 00_prix.ipynb) pour ne pas les confondre. Un notebook importé s'ouvre dans une session neuve, sans dépôt ni paquets : les étapes 3 et 4 sont à refaire dans chaque notebook importé, environ 3 minutes.
  3. Insérez une cellule en tête et exécutez-la :
!git clone https://git.persee.minesparis.psl.eu/energy-alternatives/pommes_studies/pommes-case-studies
%cd pommes-case-studies
!python --version                      # Python 3.13 sur Colab le 23/11 ; il faut 3.12 ou plus
!pip install -q -r requirements.txt

Le clone affiche sa progression ; avec -q, rien ne s'affiche et on croit la cellule bloquée.

  1. Colab a déjà importé ses propres numpy et pandas : redémarrez la session (Exécution › Redémarrer la session), puis relancez seulement %cd pommes-case-studies avant les cellules du notebook.
  2. pip se plaint de conflits avec des paquets de Colab (pandas, requests, numpy : google-colab requires pandas==…) : sans effet visible sur les cas.

Le contrôle !python A_batteries/grid.py --rapide y prend 2 à 3 minutes (178 s et 138 s sur deux essais), quatre à cinq fois plus que sur le MacBook Pro M3 Max de la section 3, et deux fois plus que sur le JupyterHub. Fermer l'onglet ne coupe pas la session : arrêtez-la par Exécution › Supprimer l'environnement d'exécution. Ce faisant, le dépôt, les paquets et vos fichiers sont effacés : téléchargez d'abord ce que vous voulez garder.

10. Un seul environnement, avec l'assistant

pommes-assistant 0.5.3, l'assistant en langage naturel pour écrire une étude pommes, est installé par requirements.txt dans le même venv que les cas, avec ses options (serveur MCP, vues, client Anthropic) README de pommes-assistant : ce que c'est, installer, trois façons de s'en servir, commandes. Pendant la semaine, tout tourne dans .venv : n'y lancez ni pip install --upgrade ni un pip install d'une autre version de pommes, qui remplacerait les versions épinglées. Le mode d'emploi détaillé de l'assistant pour la semaine est docs/cours_decembre.md.
